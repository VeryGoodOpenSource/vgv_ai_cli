# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`vgv_ai_cli` is a Dart CLI (executable `vgv_ai`) that configures Very Good AI coding agents and tooling. The repo is a **pub workspace** monorepo: the root `pubspec.yaml` declares `workspace: [packages/vgv_ai_cli]`, and the package uses `resolution: workspace`. There is one shared `pubspec.lock` at the root.

## Prerequisites

| Requirement | Why | Symptom when wrong |
|---|---|---|
| Dart SDK `^3.13.0` (CI pins `3.13.0`) | The code uses 3.13 syntax | `dart pub get` fails version solving. Worse, on 3.12 `dart analyze` reports `experiment_not_enabled_off_by_default` against the `new(...)` constructors below — **do not "fix" that by rewriting them**, fix the SDK |
| `very_good_cli ^1.5.0` | Pub workspace coverage support | Coverage dies with `Directory listing failed, path = './coverage/'`. A stale binary also prints `Invalid kernel binary format version` — reactivate with `dart pub global activate very_good_cli "^1.5.0"` |
| `jq` | Plugin hooks parse their payloads with it | Guard hooks error out; the analyze and format hooks silently do nothing |
| `gh`, authenticated with org access | This repo is private | Push and PR creation fail |

Upgrading `very_good_cli` does not reach the MCP server until the Claude session restarts — the server binds its binary at session start.

## Commands

Run these from `packages/vgv_ai_cli` unless noted.

```bash
dart pub get
```

```bash
dart format --set-exit-if-changed .
```

```bash
dart analyze --fatal-infos --fatal-warnings lib test
```

Full test run with coverage. **Run this through the `very_good_cli` MCP `test` tool, not Bash.** A plugin hook denies `dart test`, `flutter test`, and `very_good test` when they are the first two tokens of a Bash command. This is the equivalent CI step:

```bash
very_good test -j 4 --coverage --min-coverage 100 --optimization
```

Single file or single test. The MCP `test` tool accepts no file path and no name filter, so these go through Bash. `dart run test` is not caught by the hook, and CI uses this same form for its `verify-version` job:

```bash
dart run test test/src/commands/sample_command_test.dart
```

```bash
dart run test --plain-name 'tells a joke'
```

Run the CLI from source:

```bash
dart run bin/vgv_ai.dart --help
```

## Generated version file

`lib/src/version.dart` is generated by `build_version` from the `version:` field in `pubspec.yaml`. **Never edit it by hand.** After bumping the package version, regenerate:

```bash
dart run build_runner build --delete-conflicting-outputs
```

`test/ensure_build_test.dart` verifies the generated file is in sync. It is tagged `version-verify` and skipped by default (see `dart_test.yaml`); CI runs it separately:

```bash
dart run test --run-skipped -t version-verify
```

## Architecture

The entry point chain is `bin/vgv_ai.dart` → `VgvAiCliCommandRunner` (`lib/src/command_runner.dart`) → individual `Command<int>` subclasses in `lib/src/commands/`.

`VgvAiCliCommandRunner` extends `CompletionCommandRunner` from `cli_completion`, so shell completion is built in. It owns three cross-cutting behaviors that individual commands do not repeat:

- **Dependency injection.** `Logger` (mason_logger) and `PubUpdater` are constructor parameters with real defaults. Commands receive the `Logger` from the runner rather than creating one. This is what makes the whole CLI testable.
- **Error handling.** `FormatException` and `UsageException` are caught in `run()` and converted to `ExitCode.usage.code` with usage output. Commands do not handle these themselves.
- **Update check.** After every command except `update`, `_checkForUpdates()` compares `packageVersion` against pub.dev and prints an upgrade prompt. The `completion` command is fast-tracked and skips this entirely.

Commands return an `ExitCode` value from `mason_logger`, which the runner propagates to `_flushThenExit`.

### Adding a command

1. Create `lib/src/commands/<name>_command.dart` with a `Command<int>` subclass taking `required this._logger`.
2. Export it from `lib/src/commands/commands.dart`.
3. `addCommand(...)` it in the `VgvAiCliCommandRunner` constructor.

## Conventions

The codebase uses Dart 3.13 syntax. Match it:

- Unnamed constructors are declared with the `new` keyword: `new({required this._logger})`, not `SampleCommand({...})`.
- Empty class bodies use a semicolon: `class _MockLogger extends Mock implements Logger;`.

Lints are `very_good_analysis` ^11.0.0 with `public_member_api_docs` disabled. Public classes still carry `{@template}` / `{@macro}` doc comments.

### Testing

Tests exercise commands **through** `VgvAiCliCommandRunner.run(['sample'])` rather than instantiating the `Command` directly, so argument parsing and the runner's error handling are covered too. Mocks are `mocktail` (`class _MockLogger extends Mock implements Logger;`), and assertions verify logger calls (`verify(() => logger.info(...)).called(1)`) alongside the exit code.

Coverage must be 100%. New code needs tests covering success, failure, and usage-error paths.

## Claude Code setup

`.claude/settings.json` is committed and enables two plugins from the VGV marketplace: `vgv-wingspan` (brainstorm → plan → build → review workflows) and `vgv-ai-flutter-plugin` (Dart quality gates, MCP tools, hooks). Validated against wingspan `0.0.4` and the flutter plugin `0.0.5`; neither can be version-pinned from this repo, so behavior may drift.

The flutter plugin runs `dart analyze` and `dart format` automatically after **every** `.dart` Edit or Write. Analyze failures come back as work to do, which is why the SDK requirement above matters so much.

This is a pure Dart CLI, so only five of that plugin's skills apply: `green-gate`, `testing`, `license-compliance`, `very-good-analysis-upgrade`, and `dart-flutter-sdk-upgrade`. The Flutter-only ones — bloc, accessibility, material-theming, navigation, animations, internationalization, ui-package — do not.

`main` has no branch protection yet. The `permissions.deny` entries blocking force-push are a guardrail against accident, not enforcement; they do not stop `git -C . push --force` or similar.

## CI

- PR titles must be [conventional commits](https://www.conventionalcommits.org) — enforced by the `semantic_pull_request` workflow.
- Dependency licenses are restricted to `MIT`, `BSD-3-Clause`, `BSD-2-Clause`, `Apache-2.0`.
- Markdown is spell-checked with cspell against the VGV dictionaries; add project-specific words to `words` in `.github/cspell.json`.
- The `build` job in `.github/workflows/vgv_ai_cli.yaml` is currently inlined with a manual `very_good_cli ^1.5.0` pin instead of the reusable `dart_package.yml` workflow, pending very_good_workflows 1.21.1 (pub workspace coverage support). See the TODO in that file before changing it.
